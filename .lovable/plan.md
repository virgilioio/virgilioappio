## Goal
Make **Gio’s read** assess the job from the real in-job pipeline, not a thin aggregate, so it can correctly understand sourced candidates, stage positions, scorecards, conversion, and velocity.

## Confirmed findings
- **Gio’s read** is generated by `generate-job-briefing`, using `_shared/jobBriefing/buildJobSnapshot`, then deterministic detectors, then an LLM only when needed.
- The snapshot currently uses a **wrong stage identifier** for stage buckets: it builds stage IDs from `job_hiring_stages.stage_id`, while candidate associations use `job_candidate_associations.current_stage_id` as the `job_hiring_stages.id`. This can make active candidates appear unassigned/outside stages and trigger false “thin pipeline” reads.
- The “sourced candidates” count comes from a narrow regex on `candidates.source`. On the job currently open in preview, the candidate sources are `LinkedIn`, `direct`, and `public_posting`, but the existing sourced heuristic counts **0 sourced** because `LinkedIn` and `direct` do not match it.
- Gio’s read snapshot does **not** currently include scorecards, stage history/conversion, scheduled interviews, or richer per-stage velocity.

## Implementation plan

1. **Fix the stage identity bug in the briefing snapshot**
   - Use `job_hiring_stages.id` as the stage bucket key.
   - Keep `stage_id` only as the underlying global stage definition reference.
   - Ensure active candidates populate the correct stage cards and `thin_pipeline` uses the actual current stages.

2. **Centralize candidate source classification**
   - Add a small shared classifier in `_shared/jobBriefing` for source buckets:
     - `public_posting`, job boards, career site, application portal → inbound.
     - `LinkedIn`, `direct`, `manual`, `chrome`, `extension`, `apollo`, `pdl`, `coresignal`, outreach/sourcing variants → sourced.
     - Unknown values tracked separately rather than silently dropped.
   - Use it for `inbound_total`, `sourced_total`, and source breakdown evidence.

3. **Expand the deterministic job snapshot**
   Add facts Gio can safely use without inventing:
   - Per-stage active/total counts.
   - Median and max days in stage.
   - Candidate names by stage with days in stage.
   - Stage conversion metrics from historical stage moves where available.
   - Forward movement speed from `job_candidate_stage_history` / `stage_events`.
   - Rejection, offer, hire, and active counts by stage/source.
   - Scorecard summaries from `job_stage_scorecards`: counts, rating distribution, recent overview snippets, AI-draft vs submitted distinction.
   - Scheduled/completed interview counts from `scheduled_bookings`.

4. **Upgrade detectors to account for richer context**
   - Make `thin_pipeline` consider the whole pipeline and candidate progression, not only a narrow pre-interview count.
   - Avoid “No candidates / thin pipeline” when active candidates exist in later stages or there is meaningful recent movement.
   - Add evidence for bottlenecks based on median/max days in stage and stage conversion drop-offs.
   - Keep detector output deterministic so the health badge remains explainable.

5. **Update Gio’s briefing prompt and response contract**
   - Pass the expanded snapshot and detector evidence to the existing AI call.
   - Instruct Gio to prioritize pipeline reality: current candidates, movement, scorecards, stage conversion, and source mix.
   - Keep anti-hallucination rules: only cite numbers/names present in the snapshot.

6. **Keep the UI mostly intact, but feed it better data**
   - Preserve the current Gio’s read card layout and stat tiles.
   - Update the active/source qualifier text if needed so sourced/inbound/unknown counts display honestly.
   - Ensure refresh regenerates from the corrected snapshot, not stale cached assumptions.

7. **Validate against the reported job**
   - Call the briefing snapshot for the current job and verify:
     - sourced count is no longer 0 when source values indicate sourced candidates.
     - candidates appear in their actual stages.
     - false “thin pipeline / no candidates” does not fire when the pipeline is populated.
     - scorecards and movement metrics appear in the snapshot and Gio can reference them.
